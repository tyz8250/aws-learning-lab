# 04. Session Manager を使う

## 目的

SSH ポートを開けずに EC2 を操作する方法として、AWS Systems Manager Session Manager を試す。

## 前提

- EC2 インスタンスが起動している
- SSM Agent が利用できる AMI を使っている
- EC2 に適切な IAM ロールを付与できる

## 手順

1. IAM ロールを作成し、SSM 用の権限を付与する
2. EC2 インスタンスに IAM ロールを関連付ける
3. Systems Manager の Fleet Manager または Session Manager を開く
4. 対象インスタンスが表示されるか確認する
5. セッションを開始する
6. SSH の 22 番ポートを閉じても操作できるか確認する

## 概念理解

Session Manager は Systems Manager の機能で、ブラウザや CLI から EC2 に接続できます。SSH 鍵や踏み台サーバーを使わずに操作でき、接続ログを残す構成も作れます。

## つまずいた点

- EC2 に IAM ロールを付け忘れる
- SSM Agent が起動していない
- プライベートサブネットでは VPC エンドポイントや外向き通信が必要になる

## セキュリティ上の注意

- SSH ポートを閉じられるのが大きな利点
- IAM 権限で接続できる人を制御する
- セッションログを CloudWatch Logs や S3 に残すことを検討する

## 削除・課金対策

- IAM ロール自体に料金はかからない
- CloudWatch Logs や S3 に保存したログは保管料金に注意する
- 検証用 EC2 は終了する

## 学び

- EC2 管理は SSH だけではない
- IAM とログを組み合わせると運用管理しやすくなる
