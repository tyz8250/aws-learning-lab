# 02. SSH とセキュリティグループ

## 目的

EC2 インスタンスに SSH 接続し、セキュリティグループで通信を制御する考え方を理解する。

## 前提

- EC2 インスタンスを作成済み
- キーペアの秘密鍵をローカルに保存済み
- インスタンスが起動中

## 手順

1. EC2 の詳細画面でパブリック IPv4 アドレスを確認する
2. セキュリティグループのインバウンドルールを確認する
3. SSH の 22 番ポートが自分の IP からのみ許可されていることを確認する
4. 秘密鍵の権限を確認する
5. SSH 接続する
6. 接続後、OS 情報やユーザー名を確認する

## コマンド例

```sh
chmod 400 path/to/key.pem
ssh -i path/to/key.pem ec2-user@<public-ip>
```

## 概念理解

SSH はサーバーを遠隔操作するためのプロトコルです。EC2 では秘密鍵を使ってログインします。セキュリティグループはステートフルな仮想ファイアウォールで、許可した通信だけがインスタンスに届きます。

## つまずいた点

- 秘密鍵の権限が広すぎると SSH クライアントに拒否される
- ユーザー名は AMI によって異なる
- 自分の IP が変わると、以前のセキュリティグループ設定では接続できない

## セキュリティ上の注意

- SSH を `0.0.0.0/0` に開けるのは避ける
- 秘密鍵を Slack、GitHub、メモアプリなどに貼らない
- 接続元 IP を必要最小限にする
- 可能なら Session Manager で SSH なしの管理も試す

## 削除・課金対策

- SSH 接続の有無自体では課金されない
- 接続確認後、不要なインスタンスは停止または終了する
- キーペアを使わなくなったら管理対象から外す

## 学び

- 「接続できない」ときは、鍵・ユーザー名・IP・セキュリティグループを順番に確認する
- 通信を許可する範囲を具体的に説明できる状態にしておく
